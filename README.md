# fade

[English](README.en.md) · [日本語](README.ja.md) · [中文](README.zh.md)

Claude Code 전용 스킬 플러그인이다.
레포가 할 일(정적 검사, hook, 린트, 테스트, 검증 수단)은 레포에 맡기고, 플러그인은 그 위에서 리드와 워커가 일하는 방식만 담는다.
모델이 똑똑해질수록 줄을 지워 결국 0줄이 되는 것이 목표라 이름이 fade 다. 왜 이렇게 만들었는지는 [WHY.md](WHY.md) 에 있다.

## 담지 않는 것

- 검사, hook, 린트 규칙. 레포를 지키는 일은 그 레포의 검사가 맡는다. 스킬이 자기 동작에 쓰는 hook 만 스킬과 함께 둔다(`nonstop`).
- 원칙을 글로 적은 스킬.
- 레포에 묶인 값(base 브랜치, 병합 방식, 검증 수단). 그 레포에서 도는 AI 가 레포를 읽고 판단한다.
- 검증 스킬(`verify-<레포>`)과 정적 검사. 그 레포의 개발자가 만든다. 본보기는 [poteto/verification-skill-example](https://github.com/poteto/verification-skill-example) 이다.

## 전제

이 스킬들은 레포의 정적 검사, hook, 린트, 테스트가 갖춰져 있다고 보고 글을 덜어 냈다. 그것이 훌륭한 레포에서만 가져다 쓴다.

스킬에서 뺀 글과, 그 자리를 맡을 레포의 검사는 아래와 같다.

| 스킬 | 뺀 글 | 레포가 갖춰야 할 검사 |
|---|---|---|
| `nonstop` | PR 병합, 기본 브랜치로의 직접 push, 강제 push 를 하지 않는다 | 그 명령에 확인을 요구하는 권한 설정이나 hook, 원격의 브랜치 보호 |
| `nonstop` | 보호 경로를 고치지 않는다 | 보호 경로의 수정을 막는 hook |
| `nonstop` | 워크트리와 브랜치를 지우지 않는다 | 삭제 명령에 확인을 요구하는 권한 설정이나 hook |
| `nonstop` | 기기·시뮬레이터 실행과 배포를 하지 않는다 | 실행·배포 명령에 확인을 요구하는 권한 설정이나 hook |
| `dispatch` | 브랜치 이름 형식과 base 고르기 | 브랜치 이름을 보는 검사와 레포의 `CLAUDE.md` |
| `dispatch` | 병합 명령과 병합 방식 | 병합 방식을 강제하는 병합 가드 |
| `dispatch` | 병합과 삭제는 사용자의 말이 인용된 승인이 있을 때만 한다 | 병합 명령과 브랜치 삭제 명령에 확인을 요구하는 hook |
| `dispatch` | 계약의 금지 항목은 어기지 않는다 | 금지할 명령을 막는 권한 설정이나 hook |
| `debug` | 레포마다 다른 재현 방법 | 검증 스킬(`verify-<레포>`) |

`nonstop` 은 레포가 확인을 요구하는 일을 거부하는 것으로만 사람 없는 세션을 막는다. 위 네 줄의 검사가 없는 레포에서는 그 일을 막을 것이 없다.

## 설치

비공개 레포라 이 레포를 읽을 수 있는 GitHub 계정이 필요하다.

```bash
claude plugin marketplace add Hwan3434/fade
```

```bash
claude plugin install fade@fade
```

고치면서 시험할 때는 클론한 폴더를 바로 읽힌다.

```bash
claude --plugin-dir ~/workspace/fade
```

Claude 클라우드 세션은 플러그인을 읽지 않는다. 클라우드에서 쓸 레포에는 스킬 폴더의 사본을 `.claude/skills/` 에 넣는다. 사본에서는 호출 이름에 `fade:` 가 붙지 않고, `nonstop` 의 hook 경로를 `"${CLAUDE_PROJECT_DIR}"/.claude/skills/nonstop/nonstop.py` 로 고쳐야 한다.

## 스킬

`job` 이 업무의 최소 단위다. `dispatch` 와 `nonstop` 은 `job` 을 통해 일한다. `grill` 은 어느 순서에도 끼지 않는 독립 도구다. 결정이 남았을 때 누구든 부른다.

| 스킬 | 하는 일 | 부르는 방법 |
|---|---|---|
| `job` | 업무의 최소 단위. 계획서 하나(목적, 완료 기준, 사람이 볼 것, 자료, 특이사항, 사용자 있음/없음)를 받아 계획, 구현, 검증, 커밋, PR, 증거를 붙인 보고까지 끝낸다. 어느 세션에서든 돈다 | `/fade:job`, 또는 「fade:job 스킬로 아래 계획서를 수행한다」는 글을 받은 Claude 가 |
| `grill` | 남아 있는 결정을 번호와 권장 답을 붙여 끝까지 묻는다 | `/fade:grill`, 또는 Claude 가 필요할 때 |
| `dispatch` | 코드 변경 작업을 목표가 걸린 레포의 워크트리에서 도는 새 세션(워커)에 `job` 계획서로 맡기고, 보고를 옮기고, 워커가 붙인 증거를 완료 기준과 대조한다. 여러 레포에 걸치면 레포마다 워커를 따로 띄운다. Claude Desktop 에서만 된다 | `/fade:dispatch`, 또는 Claude 가 필요할 때 |
| `debug` | 실패하는 명령부터 만들고 여섯 단계로 버그를 진단한다 | `/fade:debug`, 또는 Claude 가 필요할 때 |
| `nonstop` | 지켜보는 사람 없이 작업 목록을 끝까지 돈다. 작업 하나하나를 `job` 으로 수행한다. 남은 작업이 있는 동안 턴 종료, 질문 도구, 권한 창을 hook 이 막는다 | `/fade:nonstop` 으로 사용자가 직접 |
| `nonstop` | 작업마다 받은 요청과 레포를 읽어 `job` 의 계획서를 채우고, 정한 완료 기준은 `decide` 로 남기고, 채울 수 없으면 `hold` 로 적는다. 보고는 PR 본문에 남긴다 | | |

`nonstop` 은 계획 모드에서 부르면 계획 승인 창에서 멈춘다. 사람 없이 돌릴 때는 다른 권한 모드에서 부른다.

Claude Desktop 은 다른 세션이 넘긴 지시문의 `/스킬` 을 펼치지 않는다(2026-11-20 확인). 그래서 `dispatch` 는 워커에게 슬래시 없이 「fade:job 스킬로 아래 계획서를 수행한다. 사용자: 없음」이라는 글로 시키고, 워커의 Claude 가 `job` 을 스스로 부른다. 같은 이유로 워커는 `nonstop` 으로 돌지 않는다.

## 스킬을 더할 때의 기준

- 여러 레포에서 같은 본문으로 쓰는 것만 넣는다. 한 레포에서만 쓰는 스킬은 그 레포에 둔다.
- 실제 세션에서 일어난 실패가 있을 때 더하거나 고친다.
- 과정을 적는다. 검사로 막을 수 있는 규칙은 레포의 검사로 보낸다.
- 레포에 묶인 값은 적지 않는다.
- 모델이 원래 하는 일을 적은 줄은 지운다.
- 본문은 Claude Code 기준으로만 쓴다. 다른 AI 는 고려하지 않는다.
