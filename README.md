# fade

[English](README.en.md) · [日本語](README.ja.md) · [中文](README.zh.md)

Claude Code 전용 스킬 플러그인이다. Claude 데스크톱 앱(Code 탭)과 Claude CLI 에서 쓴다. 다른 에이전트를 쓰는 사람은 스킬을 읽고 자기 환경에 맞게 고쳐 쓰면 된다. 기능을 늘리려고 만든 도구가 아니라, 줄어들려고 만든 도구다.
모델이 똑똑해질수록 글을 지워 결국 0줄이 되는 것이 목표라 이름이 fade 다. 줄어드는 것은 글이다. 과정을 지키는 구조(스크립트, 훅, 테스트)는 남는다.

## 왜 만들었나

### 궁극적인 목표

> 궁극적으로는 이 스킬이 필요 없어질 때를 바란다. 최소화하는 목적 자체가 AI 가 똑똑해져서 굳이 설명하지 않아도 될 때를 바라는 것이고, AI 가 똑똑해졌다는 전제하에 우리는 덜어냄의 미학을 진행하고 있다.

### AI 를 믿는다는 것

> AI 를 믿는다는 것은 매일 바뀐다. 새 모델이 나올 때마다. 다만 AI 를 믿는 것은 AI 에게 설명을 최소화한다는 것이지 정적 검사, 훅, 린트, 테스트를 하지 않는다는 것이 아니다. 이것들은 필수이고, 그 위에서 에이전트가 앞으로 가든 뒤로 가든 우회전하든 좌회전하든 그것을 믿는다는 것이다.

### 이 도구의 자리

> 제대로 못 만들면 만들어 주지 말고 개발자들이 만들라고 하자. 우리는 그렇게 개발자들이 만든 것 위에서 AI 를 통제하기 위한 도구다. 정적 검사 레이어 쪽은 관여하지 않는다.

### 버린 길

> 글로써 에이전트를 통제하려고 하는 것. 핵심은 이것이다.

## 어떻게 만들었나

- 레포를 지키는 일(정적 검사, hook, 린트, 테스트, 검증 수단)은 그 레포가 맡는다. fade 는 그 위에서 리드와 워커가 일하는 방식만 담는다.
- 그 일하는 방식도 글보다 구조로 지킨다. `job` 의 단계 기록은 스크립트(`job.py`)가 테스트 명령을 직접 돌려 확인한 것만 남기고, 병합 직전에 훅이 그 기록과 CI 를 본다. fade 가 싣는 구조는 레포와 상관없는 fade 자신의 작업 형식뿐이다.
- 글로 막을 수 있는 규칙이라도 검사로 막을 수 있으면 스킬에서 빼고 검사로 보낸다. 보낼 곳은 그 레포의 검사가 먼저이고, 사람마다 다른 것은 그 사람의 설정이다. 스킬에 남는 것은 과정뿐이다.
- 그래서 검사가 갖춰진 레포에서만 제대로 돈다. 사람 없이 도는 `nonstop` 은 레포가 확인을 요구하는 일을 거부하는 것으로만 멈추므로, 검사가 없는 레포에서는 그 일을 막을 것이 없다.
- 레포마다, 사람마다 다른 값(base 브랜치, 병합 방식, 브랜치 이름, 검증 방법)은 적지 않는다. 그 레포의 규칙과 그 사람의 설정이 정하고, 모델은 그것을 읽고 따른다.
- 줄을 더하려면 그 줄이 막는 실패가 실제 세션에서 확인되어야 한다. 모델이 원래 하는 일을 적은 줄은 지운다.
- 여러 레포에서 같은 본문으로 쓰는 것만 담는다. Claude 데스크톱 앱과 CLI 에서 조건을 채우는 방법까지 적는다.

## 어디로 가나

- 새 모델이 나올 때마다 줄을 하나씩 지워 본다. 모델이 그 줄 없이도 해내면 그 줄은 다시 돌아오지 않는다.
- 줄이 늘어나는 것은 실패가 확인되었을 때뿐이다. 늘어난 줄도 언젠가 지울 후보다.
- 구조도 쓰지 않게 되면 지운다. 다만 모델이 좋아졌다는 이유만으로 검사를 지우지는 않는다.
- 스킬이 하나씩 사라지고 마지막 줄까지 지워지면, 그때가 이 플러그인이 완성되는 때다.

## 스킬

- `job`: 업무의 최소 단위. 계획서 하나를 받아 테스트를 먼저 쓰고, 구현, 증거, 직접 써 보기, 코드 리뷰를 문제가 없을 때까지 되풀이한 뒤 PR, 병합, 보고까지 끝낸다. 해결하지 못하거나 사용자 결정이 필요하면 거기서 멈추고 보고한다. 사용자가 「PR 까지만」처럼 범위를 줄이면 그만큼만 한다.
- `try`: 결과물을 사용자가 쓰는 방식 그대로 직접 써 보고, 경우마다 화면과 로그를 남긴다.
- `harden`: AI 가 한 실수를 지침에 글로 더하지 않고 검사(린트, 테스트, 훅, 권한 설정)로 막는다.
- `grill`: 실행 전에 남은 결정을 번호와 권장 답을 붙여 끝까지 묻는다.
- `dispatch`: 코드 변경을 레포의 워크트리에서 도는 새 세션(워커)에 `job` 계획서로 맡기고, 워커가 붙인 증거를 완료 기준과 대조한다. 데스크톱 앱에서는 세션 도구로, CLI 에서는 `claude -p` 로 띄운다.
- `debug`: 실패하는 명령 하나부터 만들고 정해진 순서로 버그를 진단한다.
- `nonstop`: 지켜보는 사람 없이 작업 목록을 끝까지 돌며 작업마다 `job` 을 수행한다. 사용자가 직접 부를 때만 쓴다.

## 구조

- `skills/job/job.py`: `job` 의 단계 기록. 구현 전 실패(red)와 구현 후 통과(green)는 명령을 직접 돌려 확인한 것만 남긴다. 증거와 직접 써 보기는 파일이 있어야 남는다. 병합 조건의 green, 증거, 써 보기, 리뷰는 지금 커밋에서 찍힌 것만 쳐서, 고친 커밋이 생기면 다시 해야 한다. 기록은 워크트리의 git 폴더 안에 있어 커밋되지 않는다.
- `hooks/merge_gate.py`: `gh pr merge` 직전에 그 워크트리의 `job` 기록과 CI 를 본다. 빠진 것이 있거나 「PR 까지만」인 작업이면 병합을 막고 이유를 알린다. `job` 기록이 없는 곳에서는 아무것도 하지 않는다. 실수를 막는 난간이지 보안 경계가 아니다.
- `hooks/permission_gate.py`: 사람 없는 `job`(`job.py start --unattended`)에서 승인 창이 뜨려 하면 기다리지 않고 거부한다. 작업은 막힌 자리를 보고하고 끝난다. 그 밖의 세션에서는 아무것도 하지 않는다.
- `tests/`: 위 셋과 `nonstop.py` 의 테스트. PR 마다 GitHub Actions 로 돈다.

## 설치

```bash
claude plugin marketplace add Hwan3434/fade
```

```bash
claude plugin install fade@fade
```

데스크톱 앱은 같은 설정을 읽으므로 CLI 로 한 번 설치하면 둘 다에서 쓴다. Claude 클라우드 세션은 플러그인을 읽지 않는다. 클라우드에서 쓸 레포에는 스킬 폴더 사본을 `.claude/skills/` 에 넣는다.
