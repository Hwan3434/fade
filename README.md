# fade

[English](README.en.md)

Claude Code 전용 플러그인이다. 리드와 워커가 테스트 먼저부터 병합까지 일하는 방식과, 그 방식을 지키는 기록 스크립트와 훅을 담는다. 기능을 늘리려고 만든 도구가 아니라, 줄어들려고 만든 도구다.

모델이 똑똑해질수록 글을 지워 결국 0줄이 되는 것이 목표라 이름이 fade 다. 줄어드는 것은 글이다. 과정을 지키는 구조(스크립트, 훅, 테스트)는 남는다.

## 왜 만들었나

### 궁극적인 목표

> 궁극적으로는 이 스킬이 필요 없어질 때를 바란다. 최소화하는 목적 자체가 AI 가 똑똑해져서 굳이 설명하지 않아도 될 때를 바라는 것이고, AI 가 똑똑해졌다는 전제하에 우리는 덜어냄의 미학을 진행하고 있다.

### AI 를 믿는다는 것

> AI 를 믿는다는 것은 매일 바뀐다. 새 모델이 나올 때마다. 다만 AI 를 믿는 것은 AI 에게 설명을 최소화한다는 것이지 정적 검사, 훅, 린트, 테스트를 하지 않는다는 것이 아니다. 이것들은 필수이고, 그 위에서 에이전트가 앞으로 가든 뒤로 가든 우회전하든 좌회전하든 그것을 믿는다는 것이다.

### 이 도구의 자리

> 제대로 못 만들면 만들어 주지 말고 개발자들이 만들라고 하자. 우리는 그렇게 개발자들이 만든 것 위에서 AI 를 통제하기 위한 도구다. 정적 검사 레이어 쪽은 관여하지 않는다.

### 버린 길

> 글로써 에이전트를 통제하려고 하는 것. 핵심은 이것이다.

## 어디서 쓰나

| | |
|---|---|
| 에이전트 | Claude Code 전용이다. 다른 에이전트를 쓰는 사람은 스킬을 읽고 고쳐 쓴다 |
| 앱 | 정하지 않는다. Claude Code 가 도는 곳이면 터미널이든 앱이든 같다 |
| 설치 | 사람의 Claude Code 에 한 번 깐다. 레포에는 fade 를 위한 파일을 두지 않는다 |
| 실행 | 로컬에서만 돈다. 클라우드 세션은 플러그인을 읽지 않아 리드도 워커도 돌지 않는다 |
| 운영체제 | macOS 와 Linux. Windows 에서는 훅과 `job.py` 가 돌지 않는다 |

## 어떻게 만들었나

- 레포를 지키는 일(정적 검사, 훅, 린트, 테스트)은 그 레포가 맡는다. fade 는 그 위에서 리드와 워커가 일하는 방식만 담는다.
- 일하는 방식도 글보다 구조로 지킨다. `job.py` 는 명령을 직접 돌려 확인한 것만 기록하고, 병합 직전에 훅이 그 기록과 CI 를 본다.
- 검사로 막을 수 있는 규칙은 스킬에서 빼고 검사로 보낸다. 그 레포의 검사가 먼저이고, 사람마다 다른 것은 그 사람의 설정이다.
- 레포마다, 사람마다 다른 값(base 브랜치, 병합 방식, 브랜치 이름, 모델)은 적지 않는다. 그 레포의 규칙과 그 사람의 설정이 정한다.
- 줄을 더하려면 그 줄이 막는 실패가 실제 세션에서 확인되어야 한다. 훅도 같다.
- 훅은 실수를 막는 난간이지 보안 경계가 아니다. `bash -c` 나 스크립트로 감춘 명령은 잡지 못하고, 잡으려 하지도 않는다.
- 검사가 갖춰진 레포에서만 제대로 돈다.

## 어디로 가나

- 새 모델이 나올 때마다 줄을 하나씩 지워 본다. 모델이 그 줄 없이도 해내면 그 줄은 돌아오지 않는다.
- 줄이 늘어나는 것은 실패가 확인되었을 때뿐이다. 늘어난 줄도 언젠가 지울 후보다.
- 구조도 쓰지 않게 되면 지운다. 다만 모델이 좋아졌다는 이유만으로 검사를 지우지는 않는다.
- 마지막 줄까지 지워지면, 그때가 이 플러그인이 완성되는 때다.

## 스킬

| 스킬 | 하는 일 |
|---|---|
| `job` | 업무의 최소 단위. 계획서 하나를 받아 테스트 먼저, 구현, 증거, 직접 써 보기, 코드 리뷰, PR, 병합, 보고까지 끝낸다. 「PR 까지만」처럼 범위를 줄이면 그만큼만 한다 |
| `dispatch` | 코드 변경을 그 레포의 워크트리에서 도는 새 세션(워커)에 맡기고, 워커가 남긴 증거를 완료 기준과 대조한다 |
| `try` | 결과물을 사용자가 쓰는 방식 그대로 써 보고 화면과 로그를 남긴다 |
| `harden` | AI 가 한 실수를 지침의 글이 아니라 검사(린트, 테스트, 훅, 권한 설정)로 막는다 |
| `debug` | 실패하는 명령 하나부터 만들고 정해진 순서로 버그를 진단한다 |
| `grill` | 실행 전에 남은 결정을 끝까지 묻는다 |

자세한 순서는 각 스킬의 `SKILL.md` 에 있다.

## 에이전트

스킬이 띄우는 서브에이전트다. 모델은 정하지 않는다.

| 에이전트 | 하는 일 |
|---|---|
| `reviewer` | 구현자의 보고를 믿지 않고 계획서와 diff 를 대조한다. 읽기만 한다 |
| `tester` | 결과물을 사용자처럼 써 보고 보고만 한다. 고치지 않는다 |
| `hardener` | 끝난 작업의 실수를 묶어 검사 제안을 만든다. 제안만 한다 |

## 구조

| 파일 | 지키는 것 |
|---|---|
| `skills/job/job.py` | 작업 기록. 테스트의 실패와 통과는 명령을 직접 돌려 확인한 것만 남긴다. 기록은 워크트리의 git 폴더에 있어 커밋되지 않는다 |
| `hooks/merge_gate.py` | 병합 직전에 그 작업의 기록과 CI 를 본다. 빠진 것이 있으면 막는다 |
| `hooks/review_gate.py` | 리뷰를 기록하기 직전에 리뷰가 diff 를 실제로 끝까지 읽었는지 본다 |
| `hooks/lead_gate.py` | 워커가 리드의 일(사람 확인 풀기, 대조, 병합된 워크트리 지우기)을 스스로 하지 못하게 한다 |
| `hooks/permission_gate.py` | 지켜보는 사람 없는 작업에서 승인 창이 뜨면 기다리지 않고 거부한다 |
| `hooks/destructive_gate.py` | 홈 폴더 삭제, 기본 브랜치 force push 같은 되돌릴 수 없는 명령 몇 가지를 막는다. **fade 를 깐 모든 세션에 걸리는 유일한 훅이다** |
| `bin/` | `job.py` 를 경로 없이 부르게 하는 입구 |
| `tests/` | 위 전부의 테스트. PR 마다 돈다 |

- 앞의 넷은 `job` 기록이 있는 워크트리에서만 판정한다. `job` 을 쓰지 않는 곳에서는 아무것도 하지 않는다.
- 훅이 오류로 죽으면 막지 않고 평소 권한 흐름으로 넘긴다.
- 무엇을 막고 무엇을 못 막는지는 각 훅 파일의 머리 설명에 있다. `job.py` 의 명령은 `job.py` 를 인자 없이 부르면 나온다.
- 실수는 `~/.claude/fade/mistakes.jsonl` 에 쌓인다. 훅이 막을 때와 리뷰에서 고친 지적이 한 줄씩 남고, `hardener` 가 묶는다.

## 설치

```bash
claude plugin marketplace add Hwan3434/fade
```

```bash
claude plugin install fade@fade
```

끄려면 플러그인을 끈다. 훅을 하나만 골라 끌 수는 없다.
