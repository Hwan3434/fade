# nonstop

지켜보는 사람이 없다. 받은 작업을 할 수 있는 데까지 끝내 놓는 것이 목적이다. 한 작업이 막혀도 나머지는 계속한다.

작업 목록은 `nonstop.py` 로만 다룬다. `nonstop.py` 는 PATH 에 있는 명령이다(플러그인의 `bin/`). 경로를 붙이지 않고 부른다. `command -v nonstop.py` 가 아무것도 내지 않으면 `python3 "${CLAUDE_SKILL_DIR}/nonstop.py"` 를 매번 그대로 쓰고, 셸 변수에 담지 않는다. `init`, `add`, `set`, `decide` 는 한 일과 남은 작업 한 줄만 찍고, 목록 전체는 `nonstop.py show <세션>` 에서만 나온다. 아래 명령의 `<세션>` 자리에는 이 대화를 가리키는 고유한 이름을 넣는다. 환경이 대화 ID 를 주면 그것을 쓴다.

## 순서

1. 받은 요청을 작업 단위로 나눠 목록을 만든다. 서로 기대는 일은 한 작업으로 묶는다.
   `nonstop.py init <세션> "작업 제목" "작업 제목" ...`
2. 목록 순서대로 한다. 워크트리 준비나 CI 처럼 오래 걸리는 것을 기다리는 동안에는 다음 작업을 먼저 한다. 작업 하나가 정리될 때마다 상태를 바꾼다.
   - 끝났다: `nonstop.py set <세션> <번호> done "PR 주소"`. 병합했으면 병합 커밋도 적는다. PR 없이 base 에 바로 반영했으면 주소 대신 반영 커밋을, 고칠 것이 없어 끝났으면 근거를 적는다. 병합했으면(바로 반영했어도) 아래 「작업이 병합되면」을 먼저 한다.
   - 사용자만 답할 수 있는 것이 있어 더 못 간다: `nonstop.py set <세션> <번호> hold "질문 · 선택지 · 권장안 · 답이 오면 이어서 할 일"`
   - 권한이나 환경에 막혔다: `nonstop.py set <세션> <번호> blocked "막힌 자리와 사유"`
3. 남은 작업이 없으면 `nonstop.py show <세션>` 의 출력을 그대로 마지막 답으로 낸다.

## 작업 하나를 하는 방법

작업 하나하나를 `fade:job` 스킬로 수행한다(사용자: 없음). 이 스킬은 그 위에 아래만 더한다.

- 작업마다 받은 요청과 레포를 읽어 `job` 의 계획서를 채운다. 확인해 줄 사람이 없으니 스스로 정한 완료 기준은 `decide` 로 남긴다. 목적이나 완료 기준을 채울 수 없으면 `hold` 로 적는다. `job` 의 기록 전문은 그 8번 보고대로 PR 의 기록 댓글(PR 이 없으면 `job.py show --save` 의 파일)에 남는다.
- 작업마다 자기 브랜치와 PR 을 갖는다. 앞 작업의 브랜치 위에 쌓지 않는다. 앞 작업이 보류되거나 막혀도 이 작업은 혼자 선다.
- 작업의 끝은 job 의 끝이다. 기본은 병합까지이고, 사용자가 줄였으면 PR 까지다. CI 를 기다리는 동안에는 다음 작업을 먼저 하고 돌아와 병합한다.
- 원인을 찾지 못했으면 고치지 않는다. `hold` 에 찾은 데까지 적는다.
- `job` 이 멈춰서 물으라는 때는 묻지 않고 아래 「묻는 대신 하는 것」을 따른다. `job` 이 스스로 고른 것은 `nonstop.py decide <세션> <번호> "무엇을 왜 골랐는지"` 로도 남긴다.

## 작업이 병합되면

병합한 뒤 `job` 의 8번 보고를 마친 뒤에(CI 를 기다리는 동안 다른 작업을 했으면 돌아와 병합하고 보고한 뒤에) 그 작업의 워크트리와 브랜치(로컬과 원격)를 지운다. 8번의 기록 댓글과 `job.py show --save` 는 워크트리의 기록을 읽으니 지우기 전에 한다. 지우기 전 검사와 브랜치 삭제는 이 스킬 폴더 옆 `dispatch/SKILL.md` 의 「정리」 1번과 3번대로 한다. 세션 보관과 hardener 는 하지 않고, 워크트리는 그 워크트리 밖에서 `git worktree remove <워크트리>` 로 지운다.

- job 의 기록은 워크트리와 함께 사라진다. PR 이 없으면 `show --save` 가 찍은 파일의 경로를 `done` 메모에 적는다.
- 검사에 걸리면 지우지 않고, 무엇이 왜 남았는지 그 작업의 `done` 메모에 함께 적는다.
- PR 까지만인 작업, hold, blocked 인 작업, 이 세션이 도는 폴더는 지우지 않는다.

## 레포가 확인을 요구하는 일

레포가 사람의 확인을 요구하는 일은 하지 않는다. `blocked` 로 적고 다음 작업으로 간다.

## 묻는 대신 하는 것

- 사용자가 정해야 할 결정은 권장안으로 정하고 진행한다. 정한 것은 `decide` 로 남기고 PR 본문에도 적는다. 병합된 뒤에도 사용자가 그 PR 을 보고 되돌릴(revert) 수 있게 한다.
- 되돌릴 수 없는 결정(배포, 데이터 삭제, 밖으로 보내는 일)만 정하지 않는다. 그 결정 없이 할 수 있는 데까지 하고 `hold` 로 적는다. 병합은 job 의 병합 조건이 채워졌을 때만 한다.
- 권한이 거부되면 형태를 바꿔 다시 시도하지 않는다. `blocked` 로 적고 다음 작업으로 간다.
- 남은 작업이 있는 동안에는 턴을 끝내지 않고, 사용자에게 묻지 않고, 권한 승인을 기다리지 않는다. 승인이 있어야 할 수 있는 일이면 `blocked` 로 적고 다음 작업으로 간다.

남은 작업이 0 이 되면 그 뒤에는 평소처럼 사용자와 대화한다.
