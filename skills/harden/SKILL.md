# harden — 실수를 검사로

1. **실수를 한 문장으로 적는다.** 무엇을, 어디서 했고, 무엇이 망가졌는지.
2. **재현 입력을 하나 만든다.** 그 실수가 들어간 명령, diff, 파일 중 하나다. `debug` 스킬의 1단계처럼 몇 초 안에 매번 같은 결과를 내야 한다.
3. **붙일 곳을 고른다.** 위에서부터 처음 맞는 곳에 붙인다.
   1. 그 레포의 린트 규칙, 소스 검사, 테스트, CI.
   2. 그 레포의 Claude 훅이나 권한(`.claude/settings.json`).
   3. 사용자의 Claude 훅이나 권한(`~/.claude/settings.json`). 병합 방식이나 브랜치 이름처럼 사람마다 다른 취향은 여기나 2번에 둔다.
   4. fade 의 훅. 누구에게나, 어느 레포에서나 같은 실수일 때만 fade 레포에 PR 로 넣는다.
   5. 위 어느 것으로도 못 막을 때만 지침 한 줄. 가장 좁은 범위의 지침 파일에 넣고, 왜 구조로 못 막는지 같이 적는다.
4. **검사가 맞는지 보인다.** 2번의 입력을 검사가 잡는 출력과, 지금의 정상 코드와 정상 작업을 통과시키는 출력(오탐 없음)을 둘 다 남긴다.
5. **글을 지운다.** 그 실수를 막으려고 지침이나 스킬에 적어 둔 줄이 있으면 지운다. 이제 검사가 대신한다.
6. **반영한다.** 레포의 검사는 그 레포에서 `job` 으로 PR 을 낸다. 사용자 settings 는 바꿀 내용을 보여 주고 승인받은 뒤 넣는다. 권한을 푸는 변경(allow 추가, 검사 끄기)은 하지 않는다. 필요하면 사용자가 직접 넣도록 넣을 줄만 보여 준다.
