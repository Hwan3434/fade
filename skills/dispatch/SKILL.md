# dispatch — 워커에 작업 맡기기

| 용어 | 뜻 |
|---|---|
| 세션 | Claude 와의 대화 하나. 자기 폴더·기록·권한 설정을 가진다 |
| 리드 | 이 스킬을 부른 세션. 어느 레포에서 열었든, 여러 레포를 모아 둔 상위 폴더에서 열었든 같다. 워커를 띄우고, 보고를 옮기고, 증거를 완료 기준과 대조한다 |
| 워커 | 리드가 이 스킬로 띄운 세션. 목표가 걸린 레포의 자기 워크트리에서 작업 하나를 하고 병합(사용자가 줄였으면 PR)으로 끝낸다. GitHub 원격이 없는 폴더면 그 폴더에서 하고 PR 없이 끝낸다. 사용자가 열어 말을 걸 수 있다 |

리드는 워커를 띄운 뒤 구현에서 손을 뗀다.

- 호출됐다는 것이 맡기기로 한 결정이다. 결과물이 코드 변경이 아니면(답만 필요한 조사) 여기서 직접 한다.
- 계획서는 워커의 첫 지시문에, 결과는 PR(본문과 기록 댓글)에 남는다.

## 1. 계획서

워커마다 `job` 스킬의 계획서를 쓴다. 칸과 쓰는 법은 이 스킬 폴더 옆 `job/SKILL.md` 의 「계획서」 절을 읽는다. 리드는 `job` 스킬을 직접 실행하지 않는다. 사용자는 워커가 뜨면 자리를 떠나니 띄우기 전에 채운다.

- 요청이 여러 레포에 걸치면 관련 레포의 코드를 읽어 구현할 수 있는지만 판정하고, 레포별 목표로 나눈다. 한 워커의 계획서에는 그 레포의 목표만 담는다. 상세 계획, 설계, 레포 사이의 API 는 리드가 정하지 않는다. 워커가 자기 레포에서 정한다.
- 사용자가 범위를 줄였으면(「PR 까지만」) 그 말을 「특이사항」에 그대로 넣는다.

### 계획서 빈칸 검사

띄우기 전에 새 서브에이전트(이 대화를 물려받지 않는 것)에 계획서만 주고, 이것만으로 만들려면 물어야 할 것을 뽑게 한다. 워커처럼 그 레포를 읽는 것은 된다. 이 답이 있어야 워커를 띄우니 백그라운드로 띄우지 않고, 답이 올 때까지 기다리는 방식으로 띄운다. 워커가 여럿이면 계획서마다 하나씩 한 메시지에서 함께 띄우고 함께 기다린다. 나온 질문을 셋으로 나눈다.

- 이미 답 있음: 계획서나 레포에 답이 있다. 그대로 둔다.
- 사소함: 리드가 정해 계획서에 적는다.
- 사용자 결정 필요: 사용자에게 한 번에 묻고, 답을 계획서에 적는다.

## 2. 워커 띄우기

워커는 이 조건을 채워야 한다. 하나라도 채울 수단이 없으면 띄우지 않고 무엇이 없는지 사용자에게 알린다.

| 조건 | 뜻 |
|---|---|
| 자기 워크트리 | 목표가 걸린 레포의 base(그 레포의 규칙에서 읽는다)에서 딴 새 브랜치와 워크트리에서 돈다. GitHub 원격이 없는 폴더면 그 폴더에서 돌고, 같은 폴더에는 워커를 하나만 둔다 |
| 같은 환경 | 사용자의 메모리, 지침 파일, 설정을 리드와 똑같이 읽는다 |
| 사람 없이 끝까지 | 지켜보는 사람이 없어도 권한 확인에서 멈추지 않는다 |
| 끝을 안다 | 워커가 턴을 끝내면 리드가 알고, 보고 전문을 읽을 수 있다 |
| 말을 건다 | 리드가 도는 중에도, 끝난 뒤에도 워커에 이어 말할 수 있다 |
| 넘겨받는다 | 사용자가 워커 대화를 열어 직접 말을 걸 수 있다 |

먼저 같은 작업이 이미 떠 있는지 본다.

워커 모델을 정해서 띄운다. 사용자가 이번에 말한 값을 쓰고, 없으면 사용자 지침 파일에 적힌 값을 쓴다. 둘 다 없으면 워커가 리드의 모델을 물려받는다는 것을 띄우기 전에 사용자에게 한 줄로 알린다. 모델 이름은 사람마다 다른 값이라 이 스킬에 적지 않는다.

첫 지시문은 아래뿐이다(아래 「데스크톱 앱」의 같은 폴더 워커만 맨 앞에 워크트리 명령을 더 둔다). 슬래시 명령(`/스킬`)은 받는 쪽에서 펼쳐지지 않을 수 있으니 글로 시킨다.

```markdown
fade:job 스킬로 아래 계획서를 수행한다. 사용자: 없음

<계획서>
```

### 데스크톱 앱

세션 도구(`start_session`)로 띄운다.

- 레포 폴더를 `cwd` 로, `use_worktree` 를 켜고, 권한 모드는 auto(리드보다 높게는 못 띄운다), 첫 지시문을 `prompt` 로, 정한 워커 모델을 `model` 로 준다(정한 모델이 없으면 `model` 을 뺀다). 끝나면 리드가 깨어나도록 `wake_when_done` 을 켠다.
- 이어 말하기는 그 세션에 메시지를 보낸다. 넘겨받기는 사용자가 앱에서 그 세션을 연다. 세션 링크를 알린다.
- Remote Control 로 조작 중인 턴에서는 앱이 다른 폴더(`cwd`)의 세션 생성을 거부한다. 리드와 같은 폴더에는 세션이 뜬다. 거부되면 `cwd` 없이 `use_worktree` 를 끄고 띄우고, 첫 지시문 맨 앞에 워크트리를 만드는 명령(아래 CLI 의 `git fetch`, `git worktree add` 두 줄)과 「워크트리로 `cd` 한다. 이후 모든 작업은 그 워크트리 안에서 한다」를 둔다. 이 워커가 직접 만든 워크트리는 세션을 보관해도 지워지지 않으니 리드가 「정리」에서 지운다.
  - `job.py` 는 그 명령을 돌린 폴더로, fade 훅(병합 훅, 승인 창 훅)은 세션이 지금 있는 폴더로 기록을 찾는다. `git -C` 만 쓰고 `cd` 하지 않으면 훅이 기록을 못 찾아 병합 검사와 승인 창 거부가 소리 없이 빠진다. 다른 폴더로 `cd` 했으면 다음 명령에서 워크트리로 돌아온다.
  - 셸은 세션 폴더(리드의 폴더) 밖으로 `cd` 한 명령이 끝나면 리드의 폴더로 돌아간다. 워크트리가 리드의 폴더 안에 있어야 `cd` 가 이어지니, 밖이면 아래 CLI 방법을 쓴다.
  - Remote Control 에서는 사용자의 메시지로 시작한 턴에서만 세션이 뜬다. 워커가 끝나 리드가 스스로 깨어난 턴에서는 같은 폴더의 세션도 거부된다. 그때 사용자가 있으면 한 줄 보내 달라고 하고, 없으면 아래 CLI 방법을 쓴다.

### CLI (세션 도구가 없을 때)

워크트리를 만들고 그 안에서 `claude -p` 를 백그라운드로 돌린다. 브랜치 이름은 그 레포의 규칙대로 짓는다.

```bash
git -C <레포> fetch origin <base>
git -C <레포> worktree add --no-track -b <브랜치> <레포>/.claude/worktrees/<이름> origin/<base>
cd <레포>/.claude/worktrees/<이름> && claude -p "<첫 지시문>" --model <워커 모델> --permission-mode auto --permission-prompts none --output-format json
```

- 정한 워커 모델이 없으면 `--model` 을 뺀다.
- 명령이 끝나면 워커가 턴을 끝낸 것이다. 출력 JSON 의 `result` 가 보고이고, `session_id` 를 적어 둔다.
- 이어 말하기: 같은 워크트리에서 `claude -p --resume <session_id> "<말>"` 에 위와 같은 옵션을 붙인다.
- 넘겨받기: 사용자가 그 워크트리에서 `claude --resume <session_id>` 를 친다. 이 세션은 데스크톱 앱 목록에 보이지 않는다. 사용자가 있으면 이 방법으로 띄울지 먼저 묻는다.
- 권한 검사를 끄는 플래그(`--dangerously-skip-permissions`, `bypassPermissions`)는 쓰지 않는다. `--permission-prompts none` 때문에 승인이 필요한 일은 거부되고, 워커가 막힌 일로 보고한다.

띄운 뒤 사용자가 워커를 넘겨받는 방법을 알리고 턴을 끝낸다. 턴을 끝내고 기다리는 것은 워커(세션)뿐이다. 서브에이전트(계획서 빈칸 검사, `fade:hardener`)는 답을 받아야 다음 일을 하니, 「답을 기다립니다」만 남기고 턴을 끝내지 않는다.

- 한 대화를 두 곳에서 동시에 잇지 않는다. 기록이 섞인다.
- 도는 중인 워커에 기준을 더하는 메시지를 보내지 않는다. 보내면 워커의 다음 턴이 바로 시작돼, 리드가 앞 턴의 보고 알림을 받지 못한다. 더할 것은 워커가 턴을 끝낸 뒤에 보내거나 다음 작업으로 미룬다.
- 그래도 도는 워커에 말을 걸었으면, 그 워커의 직전 보고 전문을 찾아 읽고 사용자에게 옮긴 뒤에 다음으로 간다.

## 3. 워커가 턴을 끝내면

보고 전문을 읽고, 그 응답에서 바로 사용자에게 옮긴다. 알림에 보고 일부만 오면 전문을 찾아 읽는다.

- 결정할 것을 앞에 두고, 워커가 사용자에게 묻는 것(선택지, 확인 요청)은 번호째 전부 옮긴다.
- 워커의 질문에 답하기 전에 사용자가 워커 대화에서 이미 답했는지 본다.
- 계획서와 이 대화에 근거가 있는 질문은 리드가 워커에 답하고 사용자에게 한 줄로 알린다. 새 판단이 필요하면 워커가 쓴 근거째 사용자에게 옮긴다.
- 리드에서 막힌 일은 워커가 아니라 사용자에게 돌린다.

## 4. 완료 판단

워커의 기록 전문(`job.py show --full`: 실행한 명령과 출력, 화면 캡처의 절대 경로, 로그)을 읽어 완료 기준과 하나씩 대조한다. 워커의 보고에는 전문이 없고 남긴 곳만 적혀 있다. 보고가 가리키는 곳을 읽는다. PR 의 기록 댓글(`gh pr view <번호> --comments` 의 마지막 기록, 없으면 PR 본문)이거나, PR 이 없거나 댓글이 실패하면 보고가 적은 기록 파일(`job.py show --save` 가 쓴 것)이다. 워커는 기본으로 병합까지 하므로 이 대조는 병합 뒤에 하는 두 번째 확인이다. 증거가 없거나 기준과 맞지 않으면 사용자에게 보고하고, 이미 병합됐으면 되돌릴지(revert) 묻는다. `gh pr diff` 는 사용자가 묻거나 반문할 때만 본다. CI 결과도 읽는다.

증거를 낼 수단이 그 레포에 없으면 「이 레포에는 증명할 수단이 없다」고 사용자에게 보고만 하고, 수단을 만들지 않는다.

워커 보고를 받은 뒤 `fade:hardener` 에이전트를 띄워(워커의 워크트리 경로, PR 주소, PR 이 없으면 기록 파일의 경로를 준다) 제안을 사용자에게 옮긴다. hardener 도 백그라운드로 띄우지 않고 답이 올 때까지 기다리며, 워커 여럿의 보고가 함께 왔으면 한 메시지에서 함께 띄운다. 레포의 검사 제안은 사용자가 받아들이면 그 레포의 워커에 `job` 으로 맡기고, 사용자 settings 와 fade 훅은 사용자가 정한다. 정리 대상으로 표시된 실수 기록은 사용자가 지우라고 할 때만 지운다.

### 정리

PR 이 병합되거나 닫히고 위의 대조와 hardener 가 끝나면 묻지 않고 정리한다(hardener 가 그 워크트리에서 `job.py slip` 을 돌린다). PR 까지만인 작업도 그 PR 이 병합되거나 닫힐 때 정리한다. 멈춘 작업(`job.py stop`, `job.py show` 첫 줄이 「상태: 멈춤(…)」)은 정리하지 않는다.

1. **워크트리를 검사한다.** 커밋 안 된 변경이나 추적하지 않는 파일(`git -C <워크트리> status --porcelain` 에 나오는 것)이나 원격에 없는 커밋이 있으면 그 워커는 정리하지 않고 보고한다. 원격에 없는 커밋은 base 가 아니라 병합된 PR 의 head(`gh pr view <번호> --json headRefOid`)나 원격 작업 브랜치와 견준다. squash 병합이면 작업 브랜치의 커밋이 base 의 조상으로 남지 않기 때문이다. 로컬 브랜치가 그 head 와 같거나 그 조상이면 원격에 없는 커밋이 없다. PR 이 없으면(원격이 없어 base 에 바로 반영했으면) 반영한 base 와 견주고, 로컬 브랜치가 base 의 조상이면 남은 커밋이 없다.
2. **세션과 워크트리를 치운다.** 데스크톱 앱이면 세션 보관 도구로 워커 세션을 보관한다. 보관하면 앱이 그 세션의 워크트리도 지우니 1번을 먼저 끝낸다. 보관이 거부되면(auto 모드 검사, 고정한 세션, 화면에 열린 세션) 다시 시도하지 않고 남은 세션 이름을 보고에 적고, 그 워커의 로컬 브랜치는 워크트리에 체크아웃된 채라 3번에서 지우지 않는다. 리드와 같은 폴더에 띄워 워커가 직접 만든 워크트리는 보관해도 남으니, 보관된 뒤 `git worktree remove <워크트리>` 로 지우고 3번에서 브랜치도 지운다. 보관이 거부되면 이 워크트리도 지우지 않는다. 그 세션이 워크트리 안에서 이어질 수 있다. CLI 면 세션은 두고 워크트리만 지운다(`git worktree remove <워크트리>`).
3. **브랜치를 지운다.** 병합된 작업 브랜치를 로컬과 원격에서 지운다. 원격에 이미 없으면 건너뛴다. 닫히기만 한 PR 의 브랜치는 남긴다.
