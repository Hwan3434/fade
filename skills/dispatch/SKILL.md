# dispatch — 워커에 작업 맡기기

| 용어 | 뜻 |
|---|---|
| 세션 | Claude 와의 대화 하나. 자기 폴더·기록·권한 설정을 가진다 |
| 리드 | 이 스킬을 부른 세션. 어느 레포에서 열었든, 여러 레포를 모아 둔 상위 폴더에서 열었든 같다. 워커를 띄우고, 보고를 옮기고, 증거를 완료 기준과 대조한다 |
| 워커 | 리드가 이 스킬로 띄운 세션. 목표가 걸린 레포의 자기 워크트리에서 작업 하나를 하고 PR 로 끝낸다. GitHub 원격이 없는 폴더면 그 폴더에서 하고 PR 없이 끝낸다. 사용자가 열어 말을 걸 수 있다 |

리드는 워커를 띄운 뒤 구현에서 손을 뗀다. 워커가 턴을 끝내면 앱이 리드를 깨운다.

- `mcp__ccd_session__start_session` 이 없으면(터미널 CLI 등) 멈추고 그렇게 알린다.
- 호출됐다는 것이 맡기기로 한 결정이다. 결과물이 코드 변경이 아니면(답만 필요한 조사) 여기서 직접 한다.
- 계약은 워커의 첫 지시문에, 결과는 PR 본문에 남는다.

## 1. 계약

목적(사용자가 원하는 결과)만 필수다. 목적이 없거나 결정할 것이 남아 있으면 `grill` 스킬로 정한 뒤에 띄운다. 사용자는 워커가 뜨면 자리를 떠난다.

- 요청이 여러 레포에 걸치면 관련 레포의 코드를 읽어 구현할 수 있는지만 판정하고, 레포별 목표로 나눈다. 워커마다 계약을 따로 쓰고, 한 워커의 계약에는 그 레포의 목표만 담는다. 상세 계획, 설계, 레포 사이의 API 는 리드가 정하지 않는다. 워커가 자기 레포에서 정한다.
- 완료 기준은 워커를 띄우기 전에 정한다. 「무엇이 되면 끝인가」와 「그것을 어떤 실행 결과로 보여 주나」(테스트·명령 출력, 화면 캡처·로그)를 함께 적는다. 버그 수정이면 고치기 전에는 실패하는 재현 테스트를 넣는다. 사람이 봐야만 판정되는 것은 「사람이 볼 것」에 따로 적는다.
- 완료 기준은 사용자가 주면 그대로 넣고, 주지 않았으면 리드가 레포를 읽고 정해 사용자에게 확인받는다.
- 워커는 이 대화와 리드의 메모리를 보지 못한다. 티켓 본문, 계획서, 결정 사항은 지시문에 내용째 담고, 이미지 같은 자료는 절대 경로를 적는다. 레포와 전역 `CLAUDE.md` 의 내용은 워커도 읽으니 옮겨 적지 않는다.
- 사용자가 범주로 정한 것(「앱바는 전부 56」)은 범주로 적는다.
- 이번 작업에만 걸리는 제약은 사용자의 말 그대로 「특이사항」에 적는다.

## 2. 워커 띄우기

먼저 `mcp__ccd_session_mgmt__list_sessions` `{"linked": true}` 로 같은 작업이 이미 떠 있는지 본다.

`mcp__ccd_session__start_session` 인자:

| 인자 | 값 |
|---|---|
| `initiation` | `"user_asked"` |
| `context` | `"fresh"` |
| `cwd` | 목표가 걸린 레포의 메인 체크아웃. `dirname "$(git -C <그 레포> rev-parse --path-format=absolute --git-common-dir)"` 로 얻는다 |
| `use_worktree` | `true`. 앱이 만든 워크트리만 레포의 신뢰를 물려받는다 |
| `source_branch` | 그 레포의 규칙에서 읽은 base |
| `branch_name`, `name` | 짧은 이름 `[a-z0-9-]`, 24자 이하 |
| `title` | 한글 요약, 60자 이하. 요청에 티켓 키나 이슈 번호가 있으면 붙인다 |
| `background` | 왜 필요한지, 지금까지 정한 것, 제약 (80자 이상) |
| `prompt` | 아래 지시문 |

GitHub 원격이 없는 폴더는 `cwd` 를 그 폴더로, `use_worktree` 를 `false` 로 하고 `source_branch`, `branch_name` 은 넣지 않는다. 커밋과 PR 은 없다. 같은 폴더에는 워커를 하나만 띄운다.

앱이 시작을 거부하는 경우가 둘 있다.

- 다른 세션의 알림으로 시작된 턴: 거부되면 바로 사용자에게 알리고 한마디를 받아 띄운다.
- 예약으로 깨어난 턴: `user_asked` 로 불러도 거부된다. 사람 없이 돌릴 작업은 사용자가 자리에 있을 때 워커를 먼저 띄워 두고, 예약은 떠 있는 워커에 `SendMessage` 를 보내는 데 쓴다.

```markdown
# 작업: <제목>

- 사용자는 자리에 없다. 목적을 달성할 수 없거나, 목적의 일부를 남기게 되거나, 보안 문제일 때 멈춰서 묻는다. 그 밖의 선택은 스스로 고르고, 무엇을 왜 골랐는지 PR 본문에 적는다. PR 이 없는 작업이면 마지막 보고에 적는다.
- 이 지시문이 계획의 승인이다. 계획을 보여 주고 답을 기다리지 않는다.
- 계약에 든 push 와 PR 은 묻지 않고 한다.
- 보고는 결과와 결정이 필요한 것을 맨 앞에 쓴다(리드에게는 앞 400자만 간다). 완료 기준마다 원본 증거(실행한 명령과 출력, 화면 캡처의 절대 경로, 로그)를 붙인다.

## 계약
- 무엇을 어떻게: <...>
- 완료 기준: <기준마다 보여 줄 실행 결과>
- 사람이 볼 것: <없으면 "없음">
- 자료: <내용째. 없으면 "없음">
- 특이사항: <사용자의 말 그대로. 없으면 "없음">
```

띄운 뒤 세션 링크를 사용자에게 알리고 턴을 끝낸다. 워커를 떼어 내면(`detach_session`) 리드가 알림을 받지 못하니 붙여 둔다.

## 3. 워커가 턴을 끝내면

알림은 보고의 앞 400자만 준다. `list_events` 로 보고 전문을 읽고, 그 응답에서 바로 사용자에게 옮긴다.

- 결정할 것을 앞에 두고, 워커가 사용자에게 묻는 것(선택지, 확인 요청)은 번호째 전부 옮긴다.
- 워커의 질문에 답하기 전에 `list_events` 로 사용자가 워커 세션에서 이미 답했는지 본다.
- 계약과 이 대화에 근거가 있는 질문은 리드가 `SendMessage`(`to` = 워커 세션 id)로 답하고 사용자에게 한 줄로 알린다. 새 판단이 필요하면 워커가 쓴 근거째 사용자에게 옮긴다.
- 리드에서 막힌 일은 워커가 아니라 사용자에게 돌린다.

## 4. 완료 판단

워커가 보고에 붙인 원본 증거(명령 출력, 화면 캡처의 절대 경로, 로그)를 완료 기준과 하나씩 대조한다. 증거가 없거나 기준과 맞지 않는 기준은 사용자에게 보고한다. `gh pr diff` 는 사용자가 묻거나 반문할 때만 본다. CI 는 `mcp__ccd_pr__get_status`(`session_id` = 워커 세션 id)로 읽는다.

증거를 낼 수단이 그 레포에 없으면 「이 레포에는 증명할 수단이 없다」고 사용자에게 보고만 하고, 수단을 만들지 않는다.

PR 이 병합된 뒤 워커 세션을 보관한다(`archive_session`).
