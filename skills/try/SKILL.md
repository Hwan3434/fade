# try — 직접 써 보기

테스트 스크립트를 돌리는 것이 아니라 사람이 밟는 경로를 따라간다. 써 보기는 `fade:tester` 에이전트가 한다. 고친 쪽이 아닌 눈으로 보게 하려는 것이다.

1. **커밋한다.** 코드 변경을 그 레포의 브랜치 규칙대로 커밋한다. tester 는 커밋 안 된 코드 변경이 있으면 시작하지 않는다.
2. **띄운다.** `fade:tester` 에 완료 기준(경우째), 결과물의 종류(웹, iOS 앱, Android 앱, macOS 앱, CLI 등), 그 레포의 실행 방법이 적힌 곳, 사용자 있음/없음을 준다.
3. **보고를 읽는다.** 시나리오마다 기대값과 실제값, 화면과 출력 파일의 경로가 온다. 파일이 실제로 있는지 보고, 화면은 열어 본다.
4. **다르면 고친다.** 기대와 다른 경우마다 그 경우를 재현하는 테스트를 더하고 구현으로 돌아간다(job 이면 `job.py red` 부터).

- job 안에서는 `job.py tried "<무엇을 어떻게 써 봤나>" <tester 가 남긴 파일>...` 로 기록한다.
- tester 가 띄울 수 없다고 보고하면(도구 없음, 레포가 막은 실행) `job.py human "<사람이 볼 것>"` 으로 넘긴다.
- 테스트가 그린 화면(스냅샷)은 써 보기가 아니라 증거다(`job.py evidence`). 써 보기는 실제로 띄운 결과물을 사람처럼 쓴 것만이다.
