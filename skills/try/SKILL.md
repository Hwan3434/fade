# try — 직접 써 보기

테스트 스크립트를 돌리는 것이 아니라 사람이 밟는 경로를 따라간다.

1. **시나리오를 적는다.** 완료 기준의 경우(정상, 경계, 실패, 빈 값 등)마다, 사용자가 실제로 밟는 순서대로 적는다.
2. **띄운다.** 그 레포의 실행 방법(README, 지침)대로 띄운다. 레포가 막아 둔 실행(권한 설정의 deny 등)은 하지 않고 「사람이 볼 것」으로 넘긴다.
3. **써 본다.** 단계마다 화면이나 출력을 남기고, 화면에 보이는 값과 로그의 실제 값을 맞춰 본다.

   | 결과물 | 데스크톱 앱 | CLI |
   |---|---|---|
   | 웹 | 내장 브라우저 도구로 열고 누르고 입력한다 | 레포에 브라우저 자동화가 있으면 그것, 없으면 `curl` 출력 |
   | iOS 앱 | iOS 시뮬레이터 도구(화면을 뺏지 않는다) | `xcrun simctl` 로 설치·실행·`io screenshot` |
   | Android 앱 | `adb shell input tap` / `input text`, `adb exec-out screencap -p` | 같다 |
   | macOS 앱 | 화면 제어. 사용자 화면을 쓰고 앱마다 승인이 필요해서 사용자 있음일 때만 | 하지 않는다 |
   | CLI·스크립트 | 사용자처럼 명령을 친다 | 같다 |

4. **다르면 멈춘다.** 기대와 다른 경우를 찾으면 그 경우를 재현하는 테스트를 더하고 구현으로 돌아간다(job 이면 `job.py red` 부터).

- 테스트가 그린 화면(스냅샷)은 써 보기가 아니라 증거다(`job.py evidence`). 써 보기는 실제로 띄운 결과물을 사람처럼 쓴 것만이다. 실제로 띄울 수 없으면 `job.py human` 으로 넘긴다.
- 시뮬레이터나 기기 하나를 여러 세션이 같이 쓰지 않는다. 다른 세션이 쓰고 있으면 기다리거나 따로 띄운다.
- job 안에서 쓰면 `job.py tried "<무엇을 어떻게 써 봤나>" <화면·출력 파일>...` 로 기록한다.
- 비밀 값은 화면과 로그에서 `<REDACTED>` 로 가린다.
