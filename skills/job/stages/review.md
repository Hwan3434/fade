# 코드 리뷰

PR 을 열기 전에 이 브랜치의 변경을 두 축으로 리뷰한다. 둘 다 돌린다.

1. **버그 축**: `code-review` 스킬을 수준을 적어서 부른다(`medium`). 수준을 빼면 지난번에 쓴 수준으로 돈다. 첫 리뷰는 base 와의 전체 변경을, 다시 하는 리뷰는 앞 리뷰 뒤에 고친 부분을 본다.
2. **명세 축**: `job.py review-files <base>` 로 `job.py show` 출력과 base 와의 전체 diff 를 워크트리 안 `.fade-review/`(git 이 무시하는 폴더)에 쓰고, 계획서 원문을 그 폴더의 `plan.md` 로 쓴다. 세 경로를 주어 `fade:reviewer` 에이전트를 띄운다.
3. **나눈다.** 막는 지적은 테스트를 깨거나, 운영을 망가뜨리거나, 데이터나 비밀을 잃거나, 완료 기준을 못 채우는 것이다. 그 밖은 사소한 지적이다. reviewer 는 나눠서 돌려주고, `code-review` 의 지적은 이 기준으로 나눈다.
4. **막는 지적을 고친다.** 고칠 때마다 그 문제를 잡는 테스트를 먼저 더해 `red` 를 보고 고친 뒤 `green` 을 돈다. 고친 막는 지적마다 `job.py slip review "<무엇을 잘못했나>"` 로 실수 기록에 남긴다.
5. 고쳤으면 증거와 직접 써 보기를 마지막 커밋에서 다시 하고, 다시 리뷰한다.
6. 리뷰할 때마다 `job.py review <남은 막는 지적 수> "<요약>"` 으로 남긴다. 사소한 지적, 판단 보류, 고치지 않기로 한 막는 지적(오탐, 범위 밖)과 그 이유는 요약에 적는다. 고치지 않기로 한 것은 수에서 뺀다.
7. 남은 막는 지적이 0 이 되면 PR 단계로 간다. 같은 지적을 두 번 고쳐도 남으면 해결하지 못한 것이니 `job.py stop` 으로 남기고 끝낸다.
