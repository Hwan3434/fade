# 테스트 먼저

구현하기 전에 이번 작업의 완료 기준을 판정하는 테스트를 쓴다.

- 그 레포의 테스트 장치(테스트 러너, 소스 검사, 검증 스크립트)로 쓴다. 레포에 실행할 장치가 하나도 없으면 새로 만들지 않는다. `job.py no-test "<이유>"` 로 적고, 사용자 있음이면 사용자에게 알린다. 그때는 증거 단계의 명령과 직접 써 보기가 판정을 대신한다.
- 완료 기준의 경우마다(정상, 경계, 실패, 빈 값 등) 테스트를 둔다.
- 테스트만 쓴 상태에서 `job.py red "<테스트 명령>"` 을 돌린다. 이 명령이 실패해야 기록된다. 통과하면 테스트가 이번 변경을 판정하지 못하는 것이니 테스트를 고친다.
- 실패 출력이 "아직 구현이 없어서"인지 읽는다. 문법 오류나 환경 문제로 실패했으면 그것을 고친 뒤 다시 `red` 를 돈다.
- 명령은 이 작업의 테스트만 도는 좁은 명령으로 준다. `green` 이 같은 명령을 다시 돌린다.
