# 병합

PR 까지만인 작업이면 이 단계를 건너뛴다.

1. `job.py check` 로 빠진 것이 없는지 본다. 빠진 것은 채운다. 채울 수 없으면(사람이 볼 것이 남음 등) `job.py stop` 으로 남기고 끝낸다.
2. 그 레포의 병합 규칙(병합 방식, 필수 검사, 리뷰 승인)을 따른다. 병합 방식은 fade 가 정하지 않는다. 레포가 사람의 승인을 요구하면 병합하지 않고 `job.py stop` 으로 남기고 끝낸다.
3. 병합한다. 직전에 fade 훅이 기록과 CI 를 다시 본다. 훅이 막으면 이유를 채운 뒤 다시 한다. 권한 설정이 막으면 다른 방법으로 병합하지 않고 `job.py stop` 으로 막힌 자리를 남기고 끝낸다.
4. 병합 뒤 병합 커밋과 base 브랜치의 CI 결과를 `job.py merged "<병합 커밋>" "<base CI 결과>"` 로 남기고(CI 가 없으면 「CI 없음」), PR 에 같은 내용을 댓글로 남긴다. 배포처럼 병합 뒤에만 써 볼 수 있는 것은 이때 `job.py tried` 로 더한다. 병합 전의 써 보기는 로컬에서 한다.
