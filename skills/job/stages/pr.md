# PR

리뷰에서 남은 지적이 0 이 된 뒤에 연다.

그 레포의 규칙이 PR 없이 base 에 바로 반영하라고 하면 PR 을 열지 않는다. 반영 직전에 base 를 받아 `job.py check` 를 돌리고, base 를 받으며 커밋이 바뀌었으면 green, 증거, 써 보기, 리뷰를 다시 한 뒤 그 규칙대로 반영한다. 반영한 커밋은 병합 단계의 4번처럼 `job.py merged` 로 남긴다.

1. 커밋하고 push 하고, 브랜치에 PR 이 없으면 연다. 본문 맨 앞에 결과를 쓰고, 그 아래에 `job.py show --full` 의 출력을 붙인다(로그 파일은 이 맥에만 있어서 내용째 붙인다). 형식과 제목은 그 레포의 규칙을 따른다.
2. `job.py pr <PR 주소>` 로 기록한다.
3. CI 가 끝날 때까지 본다. 레포에 CI 가 없으면 없다고 보고에 적는다. 데스크톱 앱이면 PR 상태 도구로, CLI 면 `gh pr checks <번호> --watch` 로 본다.
4. CI 가 실패하거나 충돌이 나거나 리뷰 댓글이 있으면, 테스트부터 고치고 증거, 써 보기, 리뷰를 마지막 커밋에서 다시 한 뒤 push 한다. 같은 실패를 두 번 고쳐도 남으면 `job.py stop` 으로 남기고 끝낸다.
