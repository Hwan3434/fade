# PR

Claude Code 의 `/ship` 과 같은 일을 한다. 사용자 있음이면 사용자가 `/ship` 을 쳐서 이 단계를 맡길 수 있다. `/ship` 은 사용자가 칠 때만 시작되고 병합하지 않으니, 모델이 스스로 부르지 않고, `/ship` 이 끝나면 병합 단계로 넘어간다.

그 레포의 규칙이 PR 없이 base 에 바로 반영하라고 하면 이 단계 대신 그 규칙대로 반영하고, 반영한 커밋을 병합 단계의 4번처럼 `job.py merged` 로 남긴다.

1. 커밋하고 push 하고, 브랜치에 PR 이 없으면 연다. 본문 맨 앞에 결과를 쓰고, 그 아래에 `job.py show --full` 의 출력을 붙인다(로그 파일은 이 맥에만 있어서 내용째 붙인다). 형식과 제목은 그 레포의 규칙을 따른다.
2. `job.py pr <PR 주소>` 로 기록한다.
3. 이 세션에서 PR 의 변경을 리뷰한다(`code-review` 스킬이 있으면 기본 수준으로). 진짜 문제만 고치고, 고쳤으면 `job.py green` 을 다시 돌린다.
4. CI 가 끝날 때까지 본다. 레포에 CI 가 없으면 없다고 보고에 적는다. 데스크톱 앱이면 PR 상태 도구로, CLI 면 `gh pr checks <번호> --watch` 로 본다. 실패하면 원인을 고치고 다시 push 한다. 충돌이 나면 base 를 받아 풀고, 리뷰 댓글이 있으면 반영한다.
