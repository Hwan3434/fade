# job — 업무 하나

계획서 하나를 받아 끝까지 수행한다. 단계마다 이 폴더의 `job.py` 로 기록한다(아래 `job.py` 는 이 스킬 폴더의 `job.py` 를 `python3` 로 돌린다는 뜻이다). `job.py` 는 테스트 명령을 직접 돌려 확인한 것만 기록하고, 병합 직전에 fade 훅이 이 기록과 CI 를 본다. 기록이 모자라면 병합이 막힌다.

## 계획서

넘기는 글은 이 모양이다.

```markdown
fade:job 스킬로 아래 계획서를 수행한다. 사용자: <있음|없음>

# 작업: <제목>
- 목적: <사용자가 원하는 결과>
- 완료 기준: <무엇이 되면 끝인가. 기준마다 확인할 경우(정상, 경계, 실패, 빈 값 등)와 보여 줄 증거>
- 사람이 볼 것: <사람이 봐야만 판정되는 것. 없으면 "없음">
- 자료: <내용째. 없으면 "없음">
- 특이사항: <사용자의 말 그대로. 범위를 줄였으면(「PR 까지만」) 그 말도. 없으면 "없음">
```

계획서를 쓰는 쪽이 지킬 것:

- 완료 기준은 사용자가 주면 그대로 넣고, 주지 않았으면 레포를 읽고 정해 사용자에게 확인받는다.
- 받는 세션은 쓰는 세션의 대화와 메모리를 보지 못한다. 티켓 본문, 계획서, 결정 사항은 내용째 담고, 이미지 같은 자료는 절대 경로를 적는다. 레포와 전역 지침 파일의 내용은 받는 세션도 읽으니 옮겨 적지 않는다.
- 사용자가 범주로 정한 것(「앱바는 전부 56」)은 범주로 적는다.
- 이번 작업에만 걸리는 제약은 사용자의 말 그대로 「특이사항」에 적는다.

## 시작하기 전에

- 「사용자」가 적혀 있지 않으면 있음으로 본다.
- 목적이나 완료 기준이 비어 있으면, 사용자 있음이면 `grill` 스킬로 채운다. 사용자 없음이면 시작하지 않고 빈 칸을 보고한다.
- 사용자 있음이면 평소처럼 사용자와 대화한다. 아래 「사용자 없음일 때」는 적용하지 않는다.
- 작업할 브랜치와 워크트리에서 `job.py start "<작업 제목>"` 을 돌린다. 사용자 없음이면 `--unattended`, 특이사항이나 사용자가 PR 까지만 하라고 했으면 `--pr-only` 를 붙인다. 사용자가 나중에 범위를 바꾸면 `job.py scope merge|pr` 로 바꾼다.

## 사용자 없음일 때

- 계획서가 계획의 승인이다. 계획을 보여 주고 답을 기다리지 않는다. 선택은 스스로 고르고, 무엇을 왜 골랐는지 PR 본문에 적는다. PR 이 없는 작업이면 마지막 보고에 적는다.
- 계획서에 든 push, PR, 병합은 묻지 않고 한다. 승인 창이 뜨려 하면 fade 훅이 대신 거부한다.
- 멈추는 때는 아래뿐이다. 이때는 `job.py stop "<이유>"` 로 남기고, 보고하고 끝낸다. 사용자의 답을 기다리는 상태로 끝나는 것이다.
  - 같은 문제를 두 번 고쳐도 남는다(해결하지 못함).
  - 요청대로는 할 수 없어 사용자 결정이 필요하다. 목적을 달성할 수 없거나 목적의 일부를 남기게 되는 때다.
  - 보안 문제다.
  - 권한 설정이나 훅이 막았다. 형태를 바꿔 다시 시도하지 않는다.

## 단계

순서대로 한다. 단계에 도착하면 그 단계의 파일(이 스킬 폴더의 `stages/`)을 읽는다.

1. **테스트 먼저**: `stages/test-first.md`
2. **구현**: `stages/build.md`. 버그 작업이면 `debug` 스킬의 순서를 따른다.
3. **증거**: `stages/evidence.md`
4. **직접 써 보기**: `try` 스킬로 사용자가 쓰는 방식 그대로 써 본다. 기록은 `job.py tried "<무엇을 어떻게 써 봤나>" <화면·출력 파일>...` 이다. 써 볼 화면도 명령도 없는 작업이면 `job.py try-na "<이유>"`, 써 볼 것은 있는데 지금 못 하면 `job.py human "<사람이 볼 것>"` 으로 남긴다. `human` 은 써 보기를 대신하지만 남아 있으면 병합하지 않는다.
5. **코드 리뷰**: `stages/review.md`. 남은 지적이 0 이 될 때까지 되풀이한다.
6. **PR**: `stages/pr.md`
7. **병합**: `stages/merge.md`. PR 까지만인 작업은 건너뛴다.
8. **보고**: 결과와 결정이 필요한 것(멈췄으면 멈춘 이유)을 맨 앞에 쓴다(넘긴 세션에는 앞 400자만 간다). 그 아래에 `job.py show --full` 의 출력을 그대로 붙이고, 완료 기준마다 원본 증거(실행한 명령과 출력, 화면 캡처의 절대 경로, 로그)를 붙인다.

3·4·5 에서 버그나 지적이 나오면 고치고(테스트를 더했으면 1부터) 3부터 다시 돈다. 고친 커밋이 생기면 앞의 green, 증거, 써 보기, 리뷰는 낡은 것이 되어, 마지막 커밋에서 다시 하기 전에는 병합 훅이 막는다.
