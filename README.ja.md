# fade

[한국어](README.md) · [English](README.en.md) · [中文](README.zh.md)

Claude Code 専用のスキルプラグインです。
リポジトリがやるべきこと(静的検査、hook、リント、テスト、検証手段)はリポジトリに任せ、プラグインはその上でリードとワーカーが働くやり方だけを扱います。
モデルが賢くなるほど行を消し、最後は 0 行になることが目標なので、名前は fade です。なぜこう作ったかは [WHY.md](WHY.md)(韓国語)にあります。

## 入れないもの

- 検査、hook、リントのルール。リポジトリを守るのはそのリポジトリの検査の役目です。スキルが自分の動作に使う hook だけはスキルと一緒に置きます(`nonstop`)。
- 原則を文章で書いたスキル。
- リポジトリに結びついた値(base ブランチ、マージ方式、検証手段)。そのリポジトリで動く AI がリポジトリを読んで判断します。
- 検証スキル(`verify-<リポジトリ>`)と静的検査。そのリポジトリの開発者が作ります。お手本は [poteto/verification-skill-example](https://github.com/poteto/verification-skill-example) です。

## 前提

これらのスキルは、リポジトリに静的検査、hook、リント、テストが揃っている前提で文章を削っています。それらが優れたリポジトリでだけ使ってください。

スキルから削った文章と、その役目を引き受けるリポジトリの検査は次のとおりです。

| スキル | 削った文章 | リポジトリが備えるべき検査 |
|---|---|---|
| `nonstop` | PR のマージ、デフォルトブランチへの直接 push、強制 push をしない | それらのコマンドに確認を求める権限設定か hook、リモートのブランチ保護 |
| `nonstop` | 保護パスを変更しない | 保護パスの変更を防ぐ hook |
| `nonstop` | ワークツリーとブランチを削除しない | 削除コマンドに確認を求める権限設定か hook |
| `nonstop` | 実機・シミュレーターでの実行とデプロイをしない | 実行・デプロイのコマンドに確認を求める権限設定か hook |
| `dispatch` | ブランチ名の形式と base の選び方 | ブランチ名を見る検査とリポジトリの `CLAUDE.md` |
| `dispatch` | マージコマンドとマージ方式 | マージ方式を強制するマージガード |
| `dispatch` | マージと削除は、ユーザーの言葉を引用した承認があるときだけ行う | マージコマンドとブランチ削除コマンドに確認を求める hook |
| `dispatch` | 契約の禁止事項は破らない | 禁止するコマンドを防ぐ権限設定か hook |
| `debug` | リポジトリごとに違う再現方法 | 検証スキル(`verify-<リポジトリ>`) |

`nonstop` は、リポジトリが確認を求めることを拒否することでしか、人のいないセッションを守りません。上の 4 行の検査がないリポジトリでは、それらを止めるものがありません。

## インストール

非公開リポジトリなので、このリポジトリを読める GitHub アカウントが必要です。

```bash
claude plugin marketplace add Hwan3434/fade
```

```bash
claude plugin install fade@fade
```

編集しながら試すときは、クローンしたフォルダを直接読み込みます。

```bash
claude --plugin-dir ~/workspace/fade
```

Claude のクラウドセッションはプラグインを読み込みません。クラウドで使うリポジトリには、スキルフォルダのコピーを `.claude/skills/` に入れます。コピーでは呼び出し名に `fade:` が付かず、`nonstop` の hook パスを `"${CLAUDE_PROJECT_DIR}"/.claude/skills/nonstop/nonstop.py` に直す必要があります。

## スキル

| スキル | すること | 呼び方 |
|---|---|---|
| `grill` | 残っている決定を、番号と推奨回答を付けて最後まで尋ねる | `/fade:grill`、または必要なときに Claude が |
| `dispatch` | コード変更の作業を、目標のリポジトリのワークツリーで動く新しいセッション(ワーカー)に任せ、報告を伝え、ワーカーが付けた証拠を完了基準と照らし合わせる。複数のリポジトリにまたがるときはリポジトリごとにワーカーを立てる。Claude Desktop でのみ動く | `/fade:dispatch`、または必要なときに Claude が |
| `debug` | 失敗するコマンドを先に作り、6 段階でバグを診断する | `/fade:debug`、または必要なときに Claude が |
| `nonstop` | 見ている人なしで作業リストを最後までこなす。作業が残っている間は、ターンの終了、質問ツール、権限ダイアログを hook が止める | `/fade:nonstop` でユーザーが直接 |

`nonstop` をプランモードで呼ぶと、プラン承認のダイアログで止まります。人なしで回すときは別の権限モードで呼びます。

`dispatch` が立てたワーカーは `nonstop` では動きません。Claude Desktop は、他のセッションが渡した指示文の `/スキル` を展開しません(2026-11-20 確認)。そのためワーカーの指示文が権限を文章で渡します。

## スキルを足すときの基準

- 複数のリポジトリで同じ本文で使うものだけを入れる。一つのリポジトリでだけ使うスキルはそのリポジトリに置く。
- 実際のセッションで起きた失敗があるときに足すか直す。
- 手順を書く。検査で防げるルールはリポジトリの検査に回す。
- リポジトリに結びついた値は書かない。
- モデルがもともとすることを書いた行は消す。
- 本文は Claude Code 向けだけに書く。他の AI は考えない。
