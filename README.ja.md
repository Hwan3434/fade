# fade

[한국어](README.md) · [English](README.en.md) · [中文](README.zh.md)

Claude Code 専用のスキルプラグインです。機能を増やすためではなく、縮んでいくために作ったツールです。
モデルが賢くなるほど行を消し、最後には 0 行になることを目指しているので、名前は fade です。

## なぜ作ったのか

### 究極の目標

> 究極的には、このスキルが要らなくなる日を願っている。最小化する目的そのものが、AI が賢くなってわざわざ説明しなくてもよくなる日を願うことであり、AI が賢くなったという前提のもとで、私たちは引き算の美学を進めている。

### AI を信じるということ

> AI を信じるということは毎日変わる。新しいモデルが出るたびに。ただし AI を信じるとは、AI への説明を最小限にするということであって、静的検査、フック、リント、テストをしないということではない。これらは必須であり、その上でエージェントが前に進もうと後ろに戻ろうと、右に曲がろうと左に曲がろうと、それを信じるということだ。

### このツールの立ち位置

> ちゃんと作れないなら代わりに作ってあげず、開発者に作ってもらおう。私たちは、そうして開発者が作ったものの上で AI を制御するためのツールだ。静的検査のレイヤーには関わらない。

### 捨てた道

> 文章でエージェントを制御しようとすること。核心はこれだ。

## どう作ったのか

- リポジトリを守る仕事（静的検査、hook、リント、テスト、検証手段）はそのリポジトリが担います。fade はその上でリードとワーカーが働くやり方だけを持ちます。
- 文章で守らせられるルールでも、検査で防げるならスキルから外し、リポジトリの検査に回します。スキルに残るのはプロセスだけです。
- そのため、検査が揃ったリポジトリでしかうまく動きません。人のいないところで動く `nonstop` は、リポジトリが確認を求める操作を拒むことでしか止まらないので、検査のないリポジトリではその操作を止めるものがありません。
- リポジトリごとに違う値（base ブランチ、マージ方式、検証方法）は書きません。そのリポジトリで動くモデルがリポジトリを読んで判断します。
- 行を足すのは、その行が防ぐ失敗が実際のセッションで確認されたときだけです。モデルが元からやることを書いた行は消します。
- 複数のリポジトリで同じ本文のまま使うものだけを入れ、Claude Code だけを基準に書きます。

## どこへ向かうのか

- 新しいモデルが出るたびに、行を一つずつ消してみます。モデルがその行なしでもこなせたら、その行は二度と戻りません。
- 行が増えるのは失敗が確認されたときだけです。増えた行も、いずれ消す候補です。
- スキルが一つずつ消え、最後の一行まで消えたとき、それがこのプラグインの完成です。

## スキル

- `job`: 仕事の最小単位。計画書を一つ受け取り、計画、実装、検証、コミット、PR、証拠を添えた報告までやり切ります。
- `grill`: 実行前に残っている決定を、番号と推奨回答を付けて最後まで尋ねます。
- `dispatch`: コード変更を、リポジトリのワークツリーで動く新しいセッション（ワーカー）に `job` の計画書で任せ、ワーカーが添えた証拠を完了基準と照らし合わせます。
- `debug`: 失敗するコマンドを一つ作るところから始め、決まった順序でバグを診断します。
- `nonstop`: 見守る人なしにタスクリストを最後まで回し、タスクごとに `job` を実行します。ユーザーが直接呼んだときだけ使います。

## インストール

```bash
claude plugin marketplace add Hwan3434/fade
```

```bash
claude plugin install fade@fade
```

Claude のクラウドセッションはプラグインを読み込みません。クラウドで使うリポジトリには、スキルフォルダのコピーを `.claude/skills/` に置き、`nonstop` の hook パスを `"${CLAUDE_PROJECT_DIR}"/.claude/skills/nonstop/nonstop.py` に書き換えます。
